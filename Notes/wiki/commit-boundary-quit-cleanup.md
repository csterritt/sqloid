# Commit-Boundary Cancellation and Quit Cleanup

Issue #43 turns the Issue #42 write lifecycle's commit boundary into an enforced, user-visible contract and completes the accepted-quit lifecycle for writes: `beginning` and `executing` stay cancellable through the exact leased write connection; once `rollback-cleanup` or `committing` has begun the write is permanently noncancellable, Ctrl+W is answered with exactly `Commit in progress; cancellation is no longer available`, and an accepted quit waits for transaction and driver work to fully end — never abandoning cleanup — before emitting exit. The atomic boundary, quit settlement, and feedback live in the PRD's **Writes and commit boundary** section (lifecycle `builder → estimating → awaiting-confirmation → beginning → executing → rollback-cleanup or committing → committed/failed/cancelled`; the outcome-unknown terminal workflow remains Issue #45's, and write-phase in-flight feedback rendering remains Issue #44's).

## The enforced atomic commit boundary (`internal/connection/write.go`)

The pre-COMMIT decision in `run()` is now ordered and synchronized so the boundary cannot be crossed twice or raced backward:

1. **Statement success** — after the sole statement completes successfully, the write is still cancellable. The `beforeWriteCommit` barrier seam now sits here: *after* statement completion, *before* the atomic check, so tests hold the write at a genuinely cancellable point past statement success.
2. **Atomic cancellation-to-commit transition** — under one mutex (`StartedWriteRequest.mu`), the request cancellation flag is read (`Request.CancelRequested`) and `noncancellable` is set in the same critical section. A cancellation therefore either wins the flag check — even though the statement returned success — and routes to rollback cleanup, **or** arrives after crossing and is permanently disabled. Both outcomes are mutually exclusive and total.
3. **Committing announced only after crossing** — `WritePhaseCommitting` is emitted only once the check passed and the boundary is crossed, then `tx.Commit()` runs. A pre-COMMIT-cancelled write therefore never emits the committing phase (`beginning → executing → rollback-cleanup`), while an uncancelled one never emits rollback cleanup (`beginning → executing → committing`).
4. **Rollback cleanup** — `rollback()` re-establishes `noncancellable` under the mutex (the statement-failure path enters rollback cleanup directly from `executing` without passing the pre-COMMIT check), so cleanup is noncancellable from its first moment. `RollbackConfirmed` semantics and the untouched-claim rule are unchanged from Issue #42 for pre-COMMIT paths. **Issue #61**: when `res.Phase == WritePhaseCommitting` (the COMMIT itself failed), `rollback()` performs best-effort cleanup but never treats `sql.ErrTxDone` as rollback confirmation — the transaction is no longer active in `database/sql` after `Commit()` was called, but the COMMIT may have persisted at the SQLite level. `RollbackConfirmed` stays false, the original commit error is preserved (never overwritten with a less informative cleanup result), and the settled result routes through Issue #45's outcome-unknown terminal workflow.

## Permanent interrupt retirement (`StartedWriteRequest.Cancel`)

`Cancel()` takes the same mutex: before the boundary it sets the cancellation flag once and dispatches **one connection-scoped interrupt against the write's own leased connection** (the `writeLeaseHook` test seam installs a counting interrupt hook on exactly that lease); after the boundary — during rollback cleanup, during committing, or after settlement — it returns without issuing any context cancellation or driver interrupt, leaving phase, work, and settlement untouched. The lease is still released only at settlement, and repeated `Cancel` calls stay inert (Request-level idempotence preserved).

## Typed Ctrl+W routing and exact boundary feedback (`internal/ui`)

- The model gains **`writeNoncancellable`**, the typed boundary state set exactly when `applyWritePhase` accepts a `rollback-cleanup` or `committing` phase (also retiring `ActiveCancellable`/`CancelCommand`/`writeCancel`, as before). Ctrl+W routes by this state — never by phase-label text.
- **Pre-boundary**: Ctrl+W in a cancellable phase requests cancellation **once** — `writeCancelling` is set at key time and the dispatch is refused when it is already set, so repeated keys cannot issue a second cancellation request.
- **Post-boundary**: Ctrl+W during `rollback-cleanup` or `committing` returns no command, mutates nothing (phase, pending work, and settlement are untouched), and records the exact feedback `Commit in progress; cancellation is no longer available` (`CommitBoundaryFeedback`, rendered through the existing in-flight notice line). Repeated keys show the same feedback.
- **Regression and stale guards**: `applyWritePhase` rejects (as inert no-ops) a repeated current phase, any `beginning`/`executing` message once `writeNoncancellable` is set — a late or regressed phase can never cross the boundary backward and re-enable cancellation — and any message whose execution identity is not the current `writeExecution`. `startWrite` still refuses replacement work while a write pends, so no replacement database work can start across the boundary.

## Accepted-quit settlement for writes (`internal/ui`)

The shared quit confirmation (`openQuitConfirmation`/`handleQuitConfirmKey`) is available from every write phase, suspending the exact context as always:

- **Acceptance during a pending write** enters the write-side coordinator `acceptQuitWithWrite` instead of exiting: `quitWaitWrite` is set, the confirmation closes, and — for cancellable work — exactly one cancellation request is dispatched (skipped when the write is already cancelling or the boundary has been crossed). For noncancellable `rollback-cleanup`/`committing` work no interrupt is issued and the existing operation continues.
- **No exit while work remains**: the accepted quit emits no `tea.Quit` while the write is pending; unrelated interaction keeps the application alive.
- **Settlement completes the quit**: the `WriteSettledMsg` case emits `tea.Quit` only when the message actually finalized the current write (`writeFinalized` advanced from false, execution identity matching, `writePending` cleared). Stale identities neither exit nor consume the wait state; the exactly-once `internal/history` finalizer (`AppendFinalized`'s execution-identity guard plus the model's `writeFinalized` flag) guarantees the outcome is finalized exactly once — definite (`committed`/`cancelled` with confirmed rollback) or unresolved (no untouched claim, no persistence claim) — before exit.
- **Idempotence**: duplicate acceptance while waiting is a no-op that neither exits early nor requests a second cancellation; a replayed settlement message after the quit completed appends nothing and emits nothing.
- **Declined quit** restores the exact suspended write phase (pending state, phase, cancelling flag, feedback) with no cleanup side effects, and Ctrl+W remains fully live afterward.
- **No abandonment**: the sole retained write keeps its lease and executor ownership until it resolves; replacement `startWrite` is refused throughout the wait, so no transaction, driver call, or late outcome is abandoned and the process is never torn down early.

## Tests

- `internal/connection/commit_boundary_test.go` — barrier-seam coverage with the new `writeLeaseHook` seam: exactly one scoped interrupt before the boundary (`TestWriteInterruptScopedToLeaseBeforeBoundary`), no interrupt and unchanged state when `Cancel` is repeated during held rollback cleanup (`TestWriteNoInterruptDuringRollbackCleanup`), no interrupt after settlement (`TestWriteNoInterruptAfterBoundarySettlement`), and the revised `TestWriteCancellationWinsAfterStatementSuccess` holding the after-statement/before-COMMIT decision while still cancellable.
- `internal/connection/write_test.go` — the Issue #42 lifecycle suite updated to the redefined boundary: the pre-COMMIT-cancelled write's phase sequence is `beginning → executing → rollback-cleanup` (committing is announced only after crossing), `holdWriteBarrier` now also supports `WritePhaseRollbackCleanup`, and the result contracts (outcome, `RowsAffected`, `RollbackConfirmed`, lease reuse) are unchanged.
- `internal/ui/commit_boundary_test.go` — barrier-held fake-executor model tests: once-per-write pre-boundary cancellation with dedupe, exact `Commit in progress; cancellation is no longer available` with no context cancellation and untouched work in both noncancellable phases, resistance to phase regressions, duplicate phases, stale identities, and replacement-work attempts.
- `internal/ui/write_quit_settlement_test.go` — accepted quit from cancellable and noncancellable phases (committed, failed, unresolved rollback, unresolved commit), no exit while pending, exit only after settlement, exactly-once finalization with no overclaiming labels, duplicate acceptance and stale settlement resistance, declined-quit exact restoration, and replacement-work prohibition.
- `internal/history/write_quit_settlement_test.go` — result-entry assertions for quit finalization: exactly-once retention per execution ID, newest selection of the finalized entry, committed/cancelled/failed labels with untouched claims only after confirmed rollback.

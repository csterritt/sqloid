## [2026-08-31] ingest | Issue #59 percent-encode relative SQLite DSN paths

Ingested the completed Issue #59 implementation (Tasks 1–2): `internal/connection/startup.go` `mustFileURL(path)` updated so relative filesystem paths are percent-encoded through `url.URL.EscapedPath()` and placed in the URL `Opaque` field, producing `file:<escaped-path>` URIs without a `//` authority. This fixes two problems with the prior `url.URL{Scheme: "file", Opaque: path}` construction: (1) reserved characters in the raw path text (`?`, `#`, spaces) were not escaped by `String()` when placed in `Opaque`, so `?` became a query delimiter, `#` became a fragment delimiter, and spaces were left unencoded — causing the SQLite URI parser to open a differently parsed filename (e.g., `foo?bar.db` opened `foo` with query `bar.db`); and (2) using `URL.Path` for relative paths would have `String()` promote the first path segment to a URI authority (`file://.wrangler/...`), which the SQLite URI parser rejects with "invalid uri authority". The fix uses Go's `EscapedPath()` deliberately rather than pre-escaping text, so characters are encoded once (only those that need encoding) and never double-encoded. Absolute paths remain on `URL.Path` with the standard `file://` form; `EscapedPath()` escaping is applied automatically by `String()`. `dsn(path)` is unchanged in structure — it calls `mustFileURL`, sets `mode=rw` and `_busy_timeout=5000` through `url.Values`, and returns `u.String()` — so `mode=rw` (no-create), the five-second busy timeout, startup validation order, diagnostics, and no-create behavior are all unchanged; only the path serialization in the DSN differs.

# Critique a PRD

Act as a skeptical senior engineer who is a meticulous requirements, plan and code reviewer.

## Process

### 1. Collect the plan

Ask the user for the PRD to examine, and any input files that are relevant to the PRD and/or the critique.

Also ask for the file format and location where the PRD critique should be saved.

Read through the PRD and any relevant input files for:

- Missing elements
- Incomplete elements
- General quality problems
- Best practice violations
- General mistakes
- Logic correctness and edge case handling
- Error handling and logging
- Any other appropriate criteria

Note that this is a requirements-only review, there is a separate process for generating issues from the PRD, and another for generating tasks from issues.
